# Architecture Index

Use this order when making implementation decisions:

1. `PRODUCT_SPECIFICATION.md` — what V1 must do.
2. `ARCHITECTURE.md` — shared system boundaries and contracts.
3. `PLATFORM_ARCHITECTURE.md` — how each operating system implements those contracts.
4. `DATA_MODEL.md` — persisted user/product data.
5. `API_CONTRACT.md` — client/backend boundary.
6. `PRIVACY_SECURITY.md` — data and permission constraints.
7. `TEST_MATRIX.md` — real-world verification targets.
8. `ROADMAP.md` — implementation sequence.
9. `DEVELOPMENT_WORKFLOW.md` — contribution and release discipline.
10. `STATUS.md` — current state and immediate next actions.
11. `adr/` — decisions that constrain future architecture.
